Changes Made This Session

FIX-1 · BE · ItemVariantRepository.java + StockService.java
Pessimistic write lock before stock sum read
Added @Lock(PESSIMISTIC_WRITE) query method findByIdForUpdate() to ItemVariantRepository. StockService.deductStock() now calls this method first, acquiring a SELECT … FOR UPDATE on the ItemVariant row before reading the stock SUM. Under MySQL REPEATABLE_READ, locked reads see the most recent committed version — Tx B blocks until Tx A commits its deduction, then reads the updated SUM, and throws InsufficientStockException if insufficient. No oversell is possible.
FIX-2 · BE · OfflineSalesProcessorService.java
Explicit TenantContext.setCurrentShopId() at start of processQueuedSales()
Added TenantContext.setCurrentShopId(shopId) as the first statement in processQueuedSales(). When triggered by an HTTP request the TenantContextTaskDecorator already propagates the shopId correctly; when triggered from the @Scheduled path the decorator captured null and skipped the set. The explicit assignment fixes the scheduler path. The decorator's finally block still clears it on method exit — no value leaks.
FIX-3 · FE · offlineDb.js
Batch eviction of 10 SYNCED records per QuotaExceededError
Replaced deleteOldestSyncedSale() (1 record) with deleteOldestSyncedSales() (up to 10 records, single IDB transaction). The batch gives the triggering write enough headroom to succeed. Eviction only touches SYNCED records — DRAFT, SYNCING, FAILED, and CONFLICT records are never touched. QUOTA_EVICTION_BATCH = 10 is a named constant.
